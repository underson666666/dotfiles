# pytest Stopフック

`.codex/hooks.json` と `pytest_stop.py` はWindows/Linux共通です。
Codexはこのプロジェクトルートまたはそのサブディレクトリから起動してください。
Linuxでは `python3`、WindowsではPythonランチャーの `py -3` が必要です。
Codex CLIの `/hooks` で定義を確認して信頼してください。

## 実行するPython

プロジェクト直下に `.venv` がある場合、Linuxの `.venv/bin/python` または
Windowsの `.venv/Scripts/python.exe` で `-m pytest` を実行します。
`.venv` がなければフックを実行中のPythonを使います。その環境にpytestが必要です。
仮想環境自体はOS間でコピーせず、それぞれのOSで用意してください。
pytestはこのプロジェクトルートで実行します。タイムアウトは120秒、フック全体は180秒です。
タイムアウトではpytest本体を終了させますが、テストが起動した子孫プロセスの終了までは保証しません。
外部プロセスを起動するテストは、テスト側でも後始末を実装してください。

## 判定と停止

- `git status --porcelain=v1 -z --untracked-files=all` でGit作業ツリー内の `.py` の変更を調べます。
  ステージ済み・未ステージ・未追跡・削除・名前変更の旧新パスを含み、Gitで無視されたファイルは含みません。
- Pythonの変更がなければ省略します。コミット済みの変更も対象外です。
- このディレクトリに人間が `pytest.disable` を置いた場合も省略します。
  AIエージェントはこのファイルを作成・変更・削除してはいけません。
- 成功時に連続失敗回数を0にします。省略時には回数を変更しません。
- テスト失敗、収集エラー、pytest未導入、タイムアウト、Git実行エラーを失敗として数えます。
- 1～4回目は修正を要求します。5回目は修正をやめて人間へ報告するためだけに継続し、
  その後のStopは終了を許可します。失敗中に停止する応答は「成功」の証明ではありません。
- 人間の操作・判断が必要なら、フックが継続させた後の最終応答を
  `人間の対応が必要です:` で始めて原因と必要な操作を報告すると、上限前でも停止します。
- 5回到達後または人間への引き継ぎ後は、明示的な再チェックが成功するまで自動チェックを停止します。
  対処後は後述の `--retry` で再検査するか、新しいセッションを使ってください。
- 状態ファイル破損などフック自体の異常では、警告を出して停止を許可します。
  テスト成功として扱わず、人間が実行結果を確認してください。

状態と直近の失敗出力は `.state/<セッションIDのSHA-256>/` に保存し、Gitから除外します。
ログにはテストの出力が含まれるため、秘密情報を出力するテストに注意してください。
同じセッションの同時実行はロックで防止します。プロセスの強制終了後にロックが残った場合は、
実行中のフックがないことを人間が確認して該当 `lock` ディレクトリを削除するか、新しいセッションを使ってください。

## 停止後の再チェック

人間が明示的に再チェックや再開を依頼した場合に限り、プロジェクトルートで実行します。
AIエージェントが5回制限を回避するために自動で使ってはいけません。

Linux:

```sh
python3 .codex/hooks/pytest_stop.py --retry
```

Windows:

```powershell
py -3 .codex/hooks/pytest_stop.py --retry
```

Codexのツール内で実行すると、環境変数 `CODEX_THREAD_ID` のセッションを対象にします。
通常のターミナルなどでこの環境変数がない場合は `--session-id <セッションID>` も指定してください。
セッションIDは `.state` のハッシュ名ではなく元のIDです。
`--retry` は標準入力を要求せず、Pythonファイルの変更の有無に関係なくpytestを1回実行します。
ただし `pytest.disable` があれば省略し、回数と停止状態は変更しません。

成功すると回数を0にして停止状態を解除し、以後の通常Stopチェックを再開します。
失敗すると回数は最大5のまま、既存の停止状態を維持します。停止前に使った場合は失敗回数が1増えます。
再チェック成功は終了コード0、テスト失敗・フック自体の異常は終了コード1です。
`pytest.disable` による省略は終了コード0ですが、成功メッセージではなく省略メッセージが出ます。

## 検証

Linux: `.venv/bin/python -m pytest`

Windows: `.venv\Scripts\python.exe -m pytest`

フックは同期実行します。手動の中断、フック未信頼、別のStopフックによる停止などまで
防止する強制的な実行境界ではありません。
